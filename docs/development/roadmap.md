# Этапы и критерии готовности

Выполняется только этап 0. Следующий этап не начинается автоматически.

| Этап | Объём | Проверяемый критерий |
| --- | --- | --- |
| 0 | Workspace, Git, private GitHub, docs, CI | Структура и реальные проверки готовы, первоначальный commit опубликован в main; результат CI установлен |
| 1 | FastAPI, React/TS/Vite, PostgreSQL, Compose | Воспроизводимый запуск, health/readiness, миграции, реальный API/UI-сценарий с сохранением в БД; lock-файлы и проверки кода |
| 2 | Data Collection, read-only connectors | Нормализация CPU/RAM/стоимости с временными метками, единицами, полнотой и тестами на данных известного происхождения |
| 3 | Optimization Engine | Несколько кандидатов, проверяемая финансовая модель, baseline vs candidates, отличение высвобождения мощности от экономии счёта |
| 4 | Feasibility Engine, Capacity Planner | Отказ с объяснением, insufficient_data, лимиты размещения, квоты, резерв, время старта нод |
| 5 | Qwen, LangGraph | Структурированные требования, allowlist tools, валидация, ошибки API/таймауты, защита от prompt injection; без прямой инфраструктурной записи |
| 6 | Optimization Lab | Baseline/candidate на одинаковом k6-сценарии, SLO, повторные измерения и ограничения достоверности; изолированный кластер |
| 7 | Autoscaling, Capacity Guard, Safety Controller | Различение HPA/node scaling; отказ при нехватке квот, IP, инстансов или резерва; default deny |
| 8 | Approval, canary, rollback | Approval конкретной ревизии, TTL, контроль дрейфа, идемпотентность; проверенные сценарии остановки и ошибки отката |
| 9 | Проверки, безопасность, демонстрация | Сквозные сценарии, аудит прав/секретов, эксплуатационные инструкции, демонстрация с честными метриками |

## Ближайший этап 1

Выбрать совместимые версии и зафиксировать Python/npm lock-файлы. Создать модульный backend,
frontend и Compose с PostgreSQL, миграциями, health/readiness и безопасным `.env.example`.
Реализовать небольшой сквозной сценарий (например, создание проекта и вывод его в UI).
Добавить Ruff, pytest с БД, ESLint, TypeScript, frontend-проверки и Docker build.
Контракты API и модель БД документировать вместе с реализацией.
Облачные интеграции, Qwen и autoscaling сюда ещё не входят.

## Открытые решения

Провайдер для первого connector, область SLO, источник цен и обязательств,
политика хранения метрик, способ очереди, модель Qwen и место её запуска.
Эти решения принимаются при появлении данных и ограничений соответствующего этапа.
