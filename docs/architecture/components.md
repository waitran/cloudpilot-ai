# Компоненты и границы

Фундамент Backend API и Frontend реализован на этапе 1. Остальные модули ниже — проектная схема будущих этапов.

| Компонент | Вход → выход | Ответственность и запреты |
| --- | --- | --- |
| Backend API | Запрос, identity → ресурс/статус задачи | Авторизация, валидация, API-контракты, аудит; не выполняет длительный эксперимент внутри HTTP-запроса |
| Data Collection | Read-only источники → DataSnapshot | Нормализация, единицы, свежесть, полнота; не выдумывает отсутствующие значения |
| Optimization Engine | Snapshot, требования, цены → Candidates | Детерминированные расчёты стоимости и варианты CPU/RAM/машин; не исполняет изменения |
| Feasibility Engine | Требования, ограничения → заключение с причиной | Отличает доказанную невыполнимость, нехватку данных и отсутствие найденного решения |
| Capacity Planner | Профиль нагрузки, Kubernetes, квоты → envelope мощности | Requests, резерв, размещение, node pools, варианты инстансов; не обещает доступность облачных ресурсов |
| AI Agent Orchestrator | Текст пользователя, разрешённые данные → структурированное предложение | Уточнение требований и объяснение; не имеет инфраструктурных credentials и shell-доступа |
| Optimization Lab | Baseline, Candidate, сценарий → Experiment/Evaluation | Изолированные k6-тесты, SLO, повторяемость; не тестирует production без отдельного разрешения |
| Safety Controller | План, Approval, актуальное состояние → allow/deny/stop | Политики, Capacity Guard, TTL, проверка дрейфа, бюджет, canary, остановка/откат |
| Infrastructure Connectors | Разрешённая команда → результат операции | Адаптеры провайдеров, таймауты, идемпотентность, reconciliation; не принимают произвольный код LLM |
| Frontend | API-контракты → интерфейс/решение пользователя | История, сравнение, достоверность данных, подтверждение ревизии; не хранит секреты облака |

## Взаимодействие

API вызывает прикладные сценарии, те используют интерфейсы модулей. Доменные расчёты
не зависят от FastAPI, конкретного SDK облака или LLM. Контракты на границах — типизированные
модели, версии входных требований и снимков сохраняются вместе с результатом.
Infrastructure Connectors имеют раздельные интерфейсы чтения и записи.

Safety Controller — единственная точка допуска к записи. Перед исполнением нужна связка
`plan_revision + requirements_revision + snapshot_id + approval + policy_version`.
Изменение любого значимого условия требует повторной проверки, а при изменении плана — нового approval.

Состояния фоновых задач: queued/running/succeeded/failed/cancelled с причиной, временными
метками и журналом. Неизвестный результат внешнего вызова требует reconciliation до повтора.
Параллельные изменения одного целевого ресурса блокируются, чтобы откат не затёр чужую операцию.

## Финансовая модель

Учитываются валюта, период, цены, обязательства оплаты, скидки, стоимость дисков/сети,
миграции и экспериментов. Экономия requests в pod не равна снижению счёта:
если оплачиваемые ноды остались прежними, это высвобождение мощности, а не денежная экономия.
Прогнозы и подтверждённые суммы отображаются отдельно.
